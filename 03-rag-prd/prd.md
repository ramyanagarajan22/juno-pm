## Problem & user
The Problem: Prospective attendees researching an event often have questions before they register about relevant sessions, pricing, or whether the event fits their needs but had no fast way to get answers. They'd either call support (slow, costly) or, more often, simply abandon registration without ever asking.
Prevention: "Event AI Assistant" explicitly prevents attendees from abandoning registration due to an unanswered pre-registration question. By giving instant, accurate answers about sessions, pricing, and relevance at the exact moment someone is deciding whether to sign up, it removes the silent friction that was costing us registrations.

## Solution overview

**Retrieval strategy:** Hybrid

Our data behaves in two different ways. FAQs and speaker bios barely change, so we can search them like a smart lookup fast and good enough. But session details like capacity, time, and venue change constantly, so those always need to be checked live from the source. With 1,000+ sessions running across many events at once, users need answers about their own event only, not a mix of everything. This hybrid setup keeps FAQ answers quick, while making sure capacity and timing info stays accurate — so no one books a session that's actually full.

## Retrieval requirements (RAG)

- **Sources:** Juno pulls data from four places: the event management platform (sessions and capacity), FAQ pages, speaker pages, and the registration page. In terms of scale, we have 4 flagship events with 100–200 sessions each, plus 20+ world tour and smaller events with 50–75 sessions each. Multiple events can run at the same time, and some have both in-person and virtual sessions.
- **Chunking / indexing:** Hybrid (Semantic + Keyword)
- **Grounding rule:** For static content (FAQs, speaker bios), Juno shows a link back to the source page. For dynamic content (capacity, timing), Juno shows how fresh the data is instead, like "as of 2 minutes ago" since there's no fixed page to link to, just a live number that keeps changing.
- **Freshness:** Data needs to stay fresh at all times, with no difference between before the event and during the event. If a session's venue, timing, or capacity changes (like going from bookable to full), users must see that update right away, so they never act on old information.

## Out of scope

Decisions that cannot be cited to a source in the knowledge base. Anything Juno is not allowed to retrieve or act on without a human.
