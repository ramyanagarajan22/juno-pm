# AI-Native User Flow · Juno

## Entry point

**Signal type:** Specific user action

User clicks the AI assistant icon at the bottom-right corner of the event page. This opens the assistant and signals intent to ask a question, even before typing anything.

**What they see instantly**

The assistant opens as a side panel with a text input box, plus 3–4 pre-loaded frequently asked questions the user can tap directly, or they can type their own custom question.

## The flow

1. 1. Scope check — confirm the question is event related (FAQs, sessions, registration help). If it's an out-of-scope question then skip retrieval and redirect the user to support page.

2. Resolve event context — use the page the user is on if it's a specific event page; if they're on the event-agnostic home page, check if they named an event in their question, and if not, ask them to clarify.

3. Retrieve & respond — run Hybrid retrieval (semantic search for FAQs/speakers, live lookup for capacity/timing) scoped to that event, then generate the answer.
2. "Juno is reading your question..." → "Matching to the right event..." → "Pulling the latest info..."
3. Single-path. Juno only answers questions and returns session/FAQ results — it never takes actions itself. When a response includes session cards, each card has an "Add to Agenda" icon the user can click directly, but this is a UI action outside Juno's decision flow, not a second path Juno routes into.

## AI moments

**Placement:** Floating & Contextual

Output format adapts to the type of question:
1. Factual FAQ (e.g., "When is the keynote?") → direct text answer with the date/time
2. General info (e.g., "Who are the main speakers?") → plain text reply
3. Session-related (e.g., "Any marketing sessions?") → session cards with title, time, tags, and an "Add to Agenda" icon
4. Registration-related (e.g., "How do I register?") → hyperlink directly to the event registration page

Personalized answers — the right session cards, the right FAQ, the right link — increase the chance the user finds what they need and takes the next step, like adding a session to their agenda or completing registration. A generic, one-size-fits-all reply gives the user less reason to act, which works against the registration conversion goal.

## Fallbacks

**Kill switch**

Each session card has a dismiss ("X") button. Clicking it logs a background signal that the result wasn't useful, without interrupting the user. Users can also ask a follow-up question at any time to redirect Juno.

**Training signal**

Dismissing a session card only applies to session recommendations (not FAQ or text answers). It signals that specific session isn't a match for the user's preference, so Juno avoids resurfacing that same session to that user again.

**Fail-safe**

If Juno can't confidently answer a question, it tells the user it's unable to help with that specific question and routes them to the FAQ page, support page, or a support contact number/link — rather than guessing.
