# Agent Workflow Spec (AWSpec) · Juno Event AI Assistant

_Module 5. Generated by `M5 - Agent Workflow Spec Builder.html`. Paste over `05-agentic-workflows/awspec.md`._

## Goal

Assist prospective attendees by converting event inquiries into completed registrations and presenting interactive, grounded session recommendations for one-click agenda booking.

**Primary actor:** Copilot + Human-in-the-Loop (Explicit User Button Confirmation)

## Trigger

Prospective attendee opens the Juno chat drawer on the Connect 2026 page OR clicks "Add to agenda" on any landing page schedule card.

## Steps & tools

**Pattern:** ReAct (single-agent reason-act-observe loop with Copilot boundary)

| Step | Action | Tool / model | Guardrail |
|---|---|---|---|
| 1 | Read query or landing page handoff context. Verify registration state. | crm.check_attendee_status(email: string) · scope: read-only | Block booking actions if Name, Email, or Company are missing. |
| 2 | Query Connect 2026 DB for sessions matching requested track/topic. | event_db.search_sessions(track: string, query: string) · scope: read-only | Scope search to Connect 2026 (50 sessions across 5 tracks). Verify seat capacity timestamp (<2-min threshold). |
| 3 | Render inline registration form OR surface top 3 session mini-cards with capacity tags. | ui.render_interactive_card(cards: array) · scope: client-render | Maximum 3 cards per response. Include explicit [Confirm & Book Session] button on each card. |
| 4 | Capture user lead inputs or process user button click for session booking. | crm.create_attendee(...) / booking.confirm_seat(...) · scope: write-only | Perform write actions strictly upon explicit user form submission or button click. |
| 5 | Trigger confirmation state inside drawer and log conversion event. | email.send_confirmation(attendee_id: string) · scope: write-only | Never auto-book sessions based on inferred user interest. |

## Schemas

- event_db.search_sessions → { sessions: [{ id, title, track, start_time, capacity_tag }], freshness_age_sec }
- crm.create_attendee → { attendee_id, first_name, last_name, email, company, status: "registered" }
- booking.confirm_seat → { reserved_session_id, user_confirmation_flag, status: "confirmed" }
- email.send_confirmation → { message_id, status: "sent" }

## Memory (in or out of scope)

- **Episodic:** In-scope: Chat history within active session, temporary lead capture form inputs; lifetime: end of browser session.
- **Semantic:** Out of scope: Do not persist long-term user profiles across external campaigns beyond this Connect 2026 registration flow.
- **Working:** In-scope: In-flight variables (First Name, Last Name, Email, Company, Track Interest), generated Attendee ID, selected Session IDs.
- **External:** Connect 2026 Schedule DB (read-only), Lead Capture CRM (write-only), Seat Reservation System (write-only on user click).

## Human-in-the-loop

Control remains with the human user at every step. Users must manually input registration fields and click explicit action buttons to execute bookings or resolve schedule overlaps.

## Success & failure

- **Done when:** Success: Attendee registered inline and session booked via explicit user click.
Failure/Escalation: Capacity API offline or unverified capacity data (>2 min old); hands off to human support directly inside drawer.
Timeout: Inactive chat drawer session for >10 minutes resets working memory.
- **Fails safe when:** Juno reads Event DB and writes to CRM/Booking APIs only upon user button clicks. Juno CANNOT auto-book sessions, alter master schedules, edit user profiles, or access payment systems.
