## Goal

Assist potential attendees by converting event inquiries into completed registrations and automatically booking top relevant sessions based on their interests.

**Primary actor:** Agent + Human-in-the-loop

## Trigger

Potential attendee sends an inbound chat message [using the Ai assistant chatbot on the event page] containing an event timing query (e.g., "when is the event?") AND confirms intent to register ("yes").

## Steps & tools

**Pattern:** ReAct (single-agent reason-act-observe loop)

| Step | Action | Tool / model | Guardrail |
|---|---|---|---|
| 1 | Read chat message and collect user details (Name, Email, Company, Area of Interest). | event_db.search_sessions(topic: string, date: string) · scope: read-only | Agent can READ Event DB and WRITE to Registration, Booking, and Email APIs. CANNOT modify existing event schedules, edit existing attendee profiles, or delete session records. |
| 2 | Query Event DB for event schedules and matching track sessions. | crm.create_attendee(first_name: string, last_name: string, email: string, company: string) · scope: write-only |  |
| 3 | Call Registration API to register attendee and generate an Attendee ID. | booking.reserve_seats(attendee_id: string, session_ids: array) · scope: write-only |  |
| 4 | Filter and reserve top 3 non-overlapping sessions matching the user's area of interest. | email.send_confirmation(attendee_id: string, summary: string) · scope: write-only |  |
| 5 | Trigger Email API to send confirmation/calendar details and return confirmation text in chat. | _ |  |

**Schemas**

event_db.search_sessions → { sessions: [{ id, title, start_time, capacity }] }

crm.create_attendee → { attendee_id, status: "created" }

booking.reserve_seats → { status: "success", booked_ids: [] }

email.send_confirmation → { message_id, status: "sent" }

**Memory (in or out of scope)**

- **Episodic:** In-scope: Chat history within the current session, intermediate tool outputs (retrieved sessions, temporary registration tokens); lifetime: end of run.
- **Semantic:** Out of scope: Do not persist long-term attendee preferences or user profiles across future event campaigns beyond this single registration flow.
- **Working:** In-scope: In-flight user variables (First Name, Last Name, Email, Company, Interest Area), generated Attendee ID, reserved Session IDs.
- **External:** Event Schedule DB (read-only), Registration API (write-only), Session Booking API (read/write), Email Service API (write-only).

## Human-in-the-loop

Control passes back to the human if mandatory registration fields are missing, if top sessions are fully booked and require a manual alternative choice, or once the final booking confirmation is displayed.

## Success & failure

- **Done when:** Success: Attendee registered, top 3 sessions reserved, and confirmation email sent.
Failure/Escalation: Registration API returns an error or invalid user input (e.g., bad email format).
Timeout: No response from attendee for 5 minutes during data collection.
- **Fails safe when:** Agent can READ Event DB and WRITE to Registration, Booking, and Email APIs. CANNOT modify existing event schedules, edit existing attendee profiles, or delete session records.
